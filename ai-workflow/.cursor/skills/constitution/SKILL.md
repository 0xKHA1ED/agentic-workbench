# Constitution

Create, update, or review the project **constitution** — the MUST/SHOULD
principles later phases are evaluated against. Storage is `constitution.md`
resolved by `constitution_path` (project dir → `meta/constitution.md` → host
`constitution.md` / `memory/constitution.md`).

Announce: "Using constitution skill."

## Load in other flows (mandatory)

Call **`workflow_get_constitution`** (path + excerpt) at the start of:

| Flow | When |
|------|------|
| **Clarify** (`/spec-clarify`) | Step 0 with `workflow_clarify_context` (already returns `constitution_excerpt`) or this tool |
| **Analyze** (`/spec-analyze`) | Before findings; constitution MUST conflicts are CRITICAL; do not edit this file |
| **Implement** (`/implement`) | Phase 1 with the approved contract; do not contradict MUST |

If `exists` is false, note the gap and continue (do not abort). Do **not**
invent principles in chat that contradict a loaded MUST.

```json
{ "project": "<project>" }
```

## Modes

Detect from user message:

- **CREATE** (default): write or amend `constitution.md`
- **REVIEW**: read-only audit of the existing file vs current practice

If the user mixes governance with feature work, handle **only** the
constitution. Defer implementation to `/spec-clarify` / `/spec-discovery` /
`/implement`.

---

## CREATE mode

### Step 1 — Load current

Call `workflow_get_constitution`. If a file exists, treat it as the source of
truth and preserve still-applicable principles. If missing, draft from
ai-workflow defaults (tree-is-memory, weak default, falsifiable VERIFY,
clarify before claims, analyze before implement, user-only strong, MCP/CLI
persistence).

### Step 2 — Collect principles

Use user arguments if present. Otherwise infer from `meta/docs/DAILY-LOOP.md`,
`AGENTS.md`, and existing MUST/SHOULD. Ask **at most 3** questions, one at a
time, only when a MUST cannot be inferred.

### Step 3 — Write `constitution.md`

Target: the path returned by the tool, or `<project-dir>/constitution.md` for
a host initiative, or `meta/constitution.md` for this package.

Required shape (Spec Kit–style, concise):

```markdown
# <Project> Constitution

## MUST
### I. <Principle>
<declarative rule>

## SHOULD
- <guidance that is not a hard gate>

## Governance
<amendment + versioning>

**Version**: X.Y.Z | **Ratified**: YYYY-MM-DD | **Last Amended**: YYYY-MM-DD
```

Version bump: MAJOR (MUST removed/redefined), MINOR (new principle), PATCH
(wording). **Last Amended** is today when anything changes.

### Step 4 — Summary

Report version bump rationale and which flows must reload the file
(clarify / analyze / implement). Suggest a commit message; do not commit
unless asked.

---

## REVIEW mode

Read-only. Do not write `constitution.md`.

1. Call `workflow_get_constitution`.
2. Check: MUST vs SHOULD split; seven package principles present for
   `meta`; no vague "should" inside MUST; version + dates ISO; later skills
   actually load the excerpt.
3. Output only:

```markdown
## Constitution review

**Version:** …
**Path:** …

### Gaps
- <missing MUST, contradiction, or skill that never loads the file>

### Contradictions
- <skill / spec / claim vs MUST>

### Verdict
pass | amend — <one sentence>
```

If verdict is **amend**, stop and wait; do not CREATE unless the user says so.

---

## Anti-patterns

- Implementing features inside `/constitution`
- Hand-editing `nodes.yaml` because a principle changed (tree mutations still
  go through MCP/CLI)
- Diluting a MUST during analyze or implement instead of amending this file
- Dumping the full constitution into every turn when an excerpt suffices
